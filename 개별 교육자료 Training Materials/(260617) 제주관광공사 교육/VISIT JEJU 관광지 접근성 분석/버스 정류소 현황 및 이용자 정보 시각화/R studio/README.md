# 제주 버스정류소 현황 및 이용자 정보 시각화 분석 (R)

## 분석 개요

본 분석은 제주 지역의 버스정류소 위치정보와 정류소별 이용인원 데이터를 활용하여  
버스정류소의 공간적 분포와 이용 규모를 지도에 시각화하기 위해 계획한 분석입니다.

제주데이터허브에서 제공하는 버스정류소 기본정보 API를 통해  
제주 지역 버스정류소의 명칭과 경도·위도 등의 기본정보를 수집했습니다.

또한 이용자 유형별 버스정류소 이용인원 데이터를 정류소 단위로 합산하여  
각 정류소의 전체 이용 규모를 확인할 수 있는 데이터를 구축했습니다.

최종적으로는 버스정류소 기본정보와 이용인원 데이터를 결합하여  
정류소별 이용인원을 지도 위에 표시하는 것을 목표로 했습니다.

다만 두 데이터에서 사용하는 정류소 식별체계가 서로 달라  
위치정보와 이용인원을 정확하게 연결하지 못했으며,  
현재는 개별 데이터의 수집과 전처리 단계까지만 완료했습니다.

## 활용 데이터

| 데이터 | 설명 |
|---|---|
| 제주데이터허브 버스정류소 기본정보 API | 제주 지역 버스정류소의 명칭, 경도, 위도 등의 기본정보 |
| 이용자유형별버스정류소이용인원현황.csv | 기준일자, 정류소명, 이용자 유형, 이용인원 정보 |

## 분석 과정

### 1. 버스정류소 기본정보 API 수집

먼저 `버스정류소 기본정보 API 불러오기.R`을 이용하여  
제주데이터허브에서 제공하는 버스정류소 기본정보를 수집했습니다.

API 호출에는 제주데이터허브에서 발급받은 프로젝트키가 필요하며,  
한 번에 불러오는 데이터 수는 100건으로 설정했습니다.

버스정류소 기본정보는 여러 페이지로 나누어 제공되기 때문에  
페이지 번호를 순차적으로 증가시키면서 전체 데이터를 반복 수집하도록 구성했습니다.

첫 번째 페이지를 호출한 뒤 전체 데이터 수를 확인하고,  
전체 행 수와 페이지당 요청 건수를 이용하여 예상 페이지 수를 계산했습니다.

이후 각 페이지의 데이터를 차례로 수집했으며,  
반환되는 데이터가 없거나 `hasMore` 값이 거짓인 경우 수집을 종료했습니다.

API 서버에 요청이 집중되는 것을 줄이기 위해  
각 페이지 호출 사이에는 0.3초의 대기시간을 적용했습니다.

페이지별로 수집된 데이터는 하나의 데이터로 통합했습니다.

지도 시각화에 활용할 수 있도록  
버스정류소의 `longitude`와 `latitude` 변수는 숫자형으로 변환했습니다.

최종적으로 수집된 버스정류소 기본정보는  
`버스정류소_기본정보_전체.csv` 파일로 저장했습니다.

이 파일은 제주 지역 버스정류소의 위치를  
지도 위에 표시하기 위한 기초자료입니다.

### 2. 버스정류소 이용현황 데이터 전처리

다음으로 `버스정류소 이용현황 데이터 전처리.R`을 이용하여  
이용자 유형별 버스정류소 이용인원 데이터를 전처리했습니다.

원자료인 `이용자유형별버스정류소이용인원현황.csv`를  
UTF-8 인코딩으로 불러왔습니다.

데이터가 정상적으로 입력되었는지 확인하기 위해  
불러온 자료의 컬럼명을 출력하도록 구성했습니다.

이후 이용인원을 정상적으로 합산할 수 있도록  
`base_date`는 정수형으로, `user_count`는 숫자형으로 변환했습니다.

원자료는 같은 버스정류소가 기준일자와 이용자 유형에 따라  
여러 행으로 나누어져 있습니다.

따라서 `station_name`을 기준으로 데이터를 그룹화하고,  
같은 정류소에 해당하는 `user_count`를 모두 더해  
정류소별 전체 이용인원을 계산했습니다.

현재 코드에서는 `user_type`을 그룹화 기준에 포함하지 않았기 때문에  
이용자 유형별 결과가 아닌 모든 이용자 유형을 합산한 값이 생성됩니다.

또한 `base_date`도 그룹화 기준에 포함하지 않았기 때문에  
날짜별 이용인원이 아니라 원자료 전체 기간의 누적 이용인원이 계산됩니다.

합산된 결과는 이용인원이 많은 정류소부터 확인할 수 있도록  
`user_count`를 기준으로 내림차순 정렬했습니다.

최종적으로 생성된 데이터는  
`버스정류소_이용인원_정류장별합산.csv` 파일로 저장했습니다.

최종 데이터의 구성은 다음과 같습니다.

| 변수 | 설명 |
|---|---|
| station_name | 버스정류소명 |
| user_count | 해당 정류소의 전체 누적 이용인원 |

이 파일은 제주 지역에서 상대적으로 이용인원이 많은 정류소와  
이용인원이 적은 정류소를 확인하기 위한 기초자료입니다.

## 분석의 한계

버스정류소 기본정보와 이용인원 데이터에서 사용하는  
정류소 식별체계가 서로 달라 두 데이터를 정확하게 결합하지 못했습니다.

버스정류소 기본정보에는 경도와 위도가 포함되어 있지만,  
이용인원 데이터와 공통으로 사용할 수 있는 동일한 정류소 코드를 확인하지 못했습니다.

정류소명을 기준으로 결합하는 방법도 검토할 수 있지만  
다음과 같은 문제가 발생할 수 있습니다.

- 동일한 이름의 정류소가 여러 위치에 존재할 수 있음
- 도로 양방향 정류소가 같은 명칭을 사용할 수 있음
- 데이터별로 띄어쓰기나 특수문자 표기가 다를 수 있음
- 정류소 이전, 변경 또는 폐지로 명칭이 달라질 수 있음
- 두 데이터의 기준시점이 서로 다를 수 있음
- 두 정류소 코드를 연결하는 공식 매핑표가 없음

정류소명만으로 데이터를 강제로 결합할 경우  
한 정류소의 이용인원이 다른 위치에 연결될 가능성이 있습니다.

또한 현재 이용인원 데이터는 `station_name`만을 기준으로 합산했기 때문에  
같은 이름을 가진 서로 다른 정류소의 이용인원이 하나로 합쳐질 수 있습니다.

`user_type`과 `base_date`도 합산 기준에서 제외했기 때문에  
이용자 유형별 차이와 날짜별 이용 변화를 확인할 수 없습니다.

이러한 한계로 인해 버스정류소 위치와 이용인원을 결합한  
최종 지도 시각화는 완료하지 못했습니다.

## 발전 방향

우선 버스정류소 기본정보와 이용인원 데이터를 연결할 수 있는  
공식 정류소 코드 매핑자료를 확보할 필요가 있습니다.

제주데이터허브 또는 관련 데이터 제공기관을 통해  
다음과 같은 자료를 확보할 수 있습니다.

- 데이터별 정류소 코드 정의서
- 정류소 코드 대응표
- 정류소 코드 변경 이력
- 이전·변경·폐지 정류소 목록
- 버스정류소 기본정보와 이용정보 간 공식 매핑표

공식 매핑자료를 확보하기 어려운 경우에는  
정류소명만으로 단순 결합하지 않고 주소, 운행 방향, 행정동,  
통과 노선 등의 정보를 함께 활용하는 다단계 매칭이 필요합니다.

정류소명은 띄어쓰기, 괄호, 특수문자 등을 제거하여 표준화하고,  
주소나 운행 방향이 일치하는 경우에만 연결하는 방식을 적용할 수 있습니다.

이용인원 데이터는 향후 `user_type`과 `base_date`를 유지하여  
다음과 같은 세부 자료로 구축할 수 있습니다.

- 정류소별·이용자 유형별 이용인원
- 정류소별·날짜별 이용인원
- 월별 버스 이용 변화
- 평일과 주말 이용 차이
- 이용자 유형별 주요 이용 정류소

정류소 코드 문제가 해결되면  
버스정류소별 이용인원을 원의 크기나 색상으로 표현한  
Leaflet 기반 인터랙티브 지도를 제작할 수 있습니다.

이를 통해 제주 지역의 버스정류소 분포와 이용 규모를 함께 확인하고,  
이용이 집중되는 정류소와 상대적으로 이용이 적은 정류소를  
공간적으로 파악하는 분석으로 발전시킬 수 있습니다.
